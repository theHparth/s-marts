Linux/Unix Interview Notes

The original notes covered the basics well (file ops, permissions, package install, ssh, vim, a few networking commands) — expanded here with everything a real interview or real day-to-day DevOps work needs on top: process management, text processing (grep/sed/awk), redirection & pipes, cron, archiving, and links. The filesystem — navigation & the directory tree

/ ├── bin binaries — essential user commands (ls, cp, mv...) ├── etc system-wide configuration files ├── home each user's personal directory (/home/parth) ├── var variable data — logs, caches, spool files ├── usr installed software & libraries (most of the OS lives here) ├── tmp temporary files, cleared on reboot └── root the root user's home directory (not the same as /)
CommandWhat it does
pwdPrint working directory — where am I right now
ls / ls -laList directory contents / long format including hidden (dotfile) entries
cd <path>Change directory. cd .. = up one level, cd ~ = home directory
mkdir / rmdirCreate / remove an empty directory
touch fileCreate an empty file, or update its modified timestamp if it exists
cpCopy — cp -r for a whole directory
mvMove, or rename in place (same command does both)
find /path -name "*.log"Search the filesystem by name/type/size/date — more powerful, slower than locate
rm -rf — no undo, no trash can
rm deletes permanently — there's no recycle bin. -r (recursive, for directories) combined with -f (force, no confirmation prompts) is the single most dangerous common Linux command — always double-check the path before running it, especially with a wildcard.

grep, sed & awk — the classic text-processing trio

ToolJobExample
grepFind lines matching a patterngrep -i "error" app.log (case-insensitive), grep -r "TODO" . (recursive through a directory)
sedFind & replace text in a streamsed 's/foo/bar/g' file — replace every "foo" with "bar"
awkProcess text column by columnawk '{print $2}' file — print just the second column of every line
When to reach for which one
grep when you just need to find lines. sed when you need to transform text line-by-line (find & replace). awk when the data has a column/field structure and you need to extract, filter, or compute across columns (like a lightweight SQL SELECT for text files).

kill vs. kill -9 — a real interview question
Plain kill sends SIGTERM — a polite request the process can catch and use to clean up (close files, finish a transaction) before exiting. kill -9 sends SIGKILL, which the OS enforces immediately — the process gets no chance to clean up at all. Always try plain kill first; reach for -9 only when a process is genuinely unresponsive.

SSH — expanded from the original notes

ssh username@ip-address
ssh -i key.pem username@ip-address     # -i = identity file (private key)

ssh-keygen -t ed25519                   # generate a new SSH key pair
ssh-copy-id username@ip-address         # install your public key on a remote host

scp file.txt username@ip-address:/remote/path/   # copy a file TO a remote host over SSH
scp username@ip-address:/remote/file.txt .        # copy a file FROM a remote host

scp is literally "cp, but over SSH" — same mental model, remote destination.

Interview Q&A

What's the difference between kill and kill -9?
Plain kill sends SIGTERM — a request the process can catch and handle gracefully (close files, finish in-flight work) before exiting. kill -9 sends SIGKILL, enforced immediately by the OS with no chance for cleanup. Always try plain kill first; reserve -9 for a genuinely unresponsive process.
What's the difference between du and df?
du reports how much disk space specific files/directories are using — scoped to whatever path you point it at. df reports free/used space at the filesystem or mounted-partition level — a whole-disk view, not a per-file one. A directory can look small under du while df still shows a disk nearly full, if space is consumed elsewhere.
What's the difference between a symbolic link and a hard link?
A symbolic link is a pointer to a path — like a shortcut — and breaks if the original is deleted or moved. A hard link is another name for the exact same data on disk; the data isn't actually freed until every hard link pointing to it is removed. Hard links can't cross filesystems or point at directories; symbolic links can do both.
When would you use awk instead of grep or sed?
grep finds matching lines. sed transforms text line-by-line (find & replace). awk is for column/field-structured data — extracting a specific column, filtering rows by a field's value, or computing across columns — closer to a lightweight SQL query over a text file than either of the other two.
